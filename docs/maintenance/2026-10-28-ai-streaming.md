# 统一 AI 流式回答

目标：全局、文章、笔记和简历助手，以及简历诊断／分块改写、Mock 出题／评价，共用真实模型流和前端读取机制。

## 方案与约束

- 现有 JSON 接口保留；前端通过 `Accept: text/event-stream` 请求同一路径的 SSE 响应，不新增平行业务流程。
- 请求范围校验、检索、模型生成、最终校验与数据库提交沿用现有逻辑。只有 Provider 调用切换成上游真实流式请求。
- SSE 使用 `start`、`sources`、`delta`／`replace`、`result`、`error`。中间内容为预览；只有 `result` 表示业务成功。结构化结果仅展示文本字段，完整 JSON 通过校验后才用于操作。
- 不伪造打字动画；不自动重放已提交的生成请求。流结束但没有结果时提示中断，保留输入和已显示预览。账号切换后的旧流不能更新新账号界面。
- 初次鉴权错误保留 HTTP 状态以兼容会话刷新；生成期间用心跳保持连接，禁止代理缓冲和压缩。

## 验证结果

- 前端回归：162 项通过，包含 SSE 分包、跨字节中文、完整结果前显示、断流保留输入、账号切换、部分引用标记隐藏与结构化预览不提前应用。
- 后端全量回归：222 项通过；随后补充结构化反馈校验失败场景和 Unicode 预览边界，流式专项 7 项通过。
- 完整构建：Vue 类型检查、Vite 与 VitePress 均通过；手册仍有依赖分块体积提示。
- 流式 ASGI 测试在接口返回前接收首段正文；上游适配测试确认发送 `stream: true`，并在读取后续分段前发出当前文字。
- 当前维护文档本地链接检查和 `git diff --check` 通过。

测试使用隔离数据和模拟的上游分块，不调用真实模型密钥。尚未部署或连接真实模型／公网网关验收；发布时同步更新前端和 API，并检查服务商支持与反向代理配置。数据库 SQL 与 PDF renderer 无需修改。

## 独立审查后的补强

- 为简历加载、版本生成及 PDF 异步回填增加账号／请求代次检查；账号切换时清理旧 JD、手工输入与文件状态。延迟到达的旧账号数据不能恢复到新界面。
- 流式结果完成后、缓存回填与历史预加载之前，再次使相关缓存失效；流失败或取消也使不确定的相关快照失效，避免生成期间读取的旧历史覆盖新结果。
- 上述竞态测试均先复现失败，再修复通过；最终前端套件 162 项通过。
