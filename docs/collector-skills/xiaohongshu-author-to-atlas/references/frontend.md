# 前端页面、正文格式与合集编号

本文件是 Atlas 接入时的展示契约。先核对现有组件和项目内容指南；符合要求的实现直接复用。用户只要求 Markdown 或只优化 skill 时，不自行修改应用、登录设置或部署。该文档描述的目标不能当作当前页面已经实现的证据。

## 信息架构与视觉

知识学习标签顺序固定为：GTM 概览 → GTM 专有名词库 → 爆品操盘GTM → 在职经验。岗位 JD 放在面经与 Mock 区域，与面经并列；旧 JD 入口兼容跳转。资料区不提供“刷新资料”按钮；首次加载、筛选和搜索仍能正常更新数据。

沿用 Atlas 当前的米白背景、克莱因蓝强调色、细边框和留白，复用已有卡片、图标、筛选器及分页组件。桌面通常三列，窄屏两列，手机单列；每页仍最多九项，不因响应式布局改变每页数量。不为新增作者另做一套主题或引入无关设计依赖。

### 在职经验首页

- 整位博主的公开图文用一个文件夹卡片表示；文件夹图标、博主显示名、文章数、简短介绍和“打开文件夹”入口。
- 普通零散资料保持单篇卡片；同一作者曾被零散收录，不足以自动把其所有资料视为完整合集。
- 按显式 author_collection_id 分组，不按昵称、标签或采集日期分组。合集里已经出现的文章不在首页再重复显示。
- 每个文件夹只占一个展示块；“资料总篇数”和“展示块数”分开计算。例如一个有二十篇的文件夹加八篇单篇，共九块，首页只有一页。
- 目录是前端视图分组，不为模拟文件夹而移动/合并源 Markdown，不创建重复知识源。

### 文件夹内页

展示返回在职经验、博主名、篇数及“从旧到新”的排序说明。帖子卡片显示：合集序号、标题、实质摘要、原始页面日期、必要标签。隐藏内部稳定 L 编号作为卡面主编号；内部身份仍供溯源和引用使用。

路由可沿用 /learn?kind=learning&collection=<稳定合集ID>，page 保存首页页码，postPage 保存合集内页码。刷新、浏览器后退、详情返回应保留所处文件夹、筛选条件及页码；不要从第十七页读一篇后回到第一页。

空列表给出简洁空态，加载时不把旧内容误当最终结果。只在列表就绪后核对页码和卡片数量，点击后立即读取可能仍是 loading；验收应等目标状态，不能把过早断言当作页面故障，也不能未验收就声称返回位置正确。

## 编号：身份与展示严格分离

| 字段/概念 | 用途 | 规则 |
| --- | --- | --- |
| id、文件路径 | 数据库、路由、引用、RAG 身份 | 稳定保留，如 research-l31 |
| source_note_id | 全库稳定资料编号 | 保留 L31/L100，不复用、不重写成 L01 |
| 合集内展示序号 | 当前博主全集的阅读顺序 | 每位博主独立从 1 开始，1、2、3…N |

**处理顺序：取全作者数据 → 排除不可展示项 → 时间升序 → 生成全集序号 → 搜索/筛选 → 每页九项。** 第 1 页为 1–9，第 2 页为 10–18；不能每页重新从 1，也不能直接显示 L31、L100 或从全库计数继续。

筛选保留全集原序号，例如命中全集第 2、10、18 篇时仍显示 2、10、18，恢复全部后仍是 1…N。不要按搜索接口返回的子集重算全集序号；可把匹配 ID 集合与完整编号映射相交。未完成/视频/排除项不占最终可阅读篇号，已有来源若属于该合集且可展示，应在全集中参与排序和计数。

示意代码，调用当前项目等价函数即可，不要求复制或新增抽象：

```typescript
const ordered = oldestFirst(allAuthorPosts.filter(isVisible))
const numbered = ordered.map((post, index) => ({ ...post, displayNumber: index + 1 }))
const matches = numbered.filter(matchesCurrentSearch)
const page = cardPage(matches, requestedPage) // 每页 9 项，并夹紧到有效页
```

使用稳定 post.id 作为组件 key、详情链接和 AI 引用。展示序号不写进永久标题、文件名或稳定编号。增量加入更早的帖子会改变后续展示序号，这是时间视图的预期变化；不因此批量改写原 Markdown 或旧引用。

## 时间与顺序

优先来源明确的完整发布时间（published_at/source_published_at），不能用 collected_at 代替发布时间。明确为编辑时间的字段不是原始发布时间；不按“05-22”这样的残缺字符串跨年排序，不猜补年份，不受主页置顶顺序影响。

现有 Atlas 小红书来源缺完整发布时间时可沿用已经核对过的帖子 ID 创建序列作为后备，并说明是创建顺序；原显示日期仍照录。对不支持该规则的来源不可直接照搬，顺序不可确定的项放末尾并稳定排序/标明未知。相同时间按稳定身份确定次序，不随接口返回顺序抖动。不能用 L 编号数值代替帖子时间。

## 每页九块

知识资料、面经、岗位 JD、学习笔记以及已有简历/Mock 历史均复用每页九项规则。首页以文件夹＋单篇为单位，文件夹内以帖子为单位。后端 API 的取数页大小与前端九项展示是两回事：必须取得完整列表才能计算合集篇数、时间顺序和序号，尤其注意接口的单页上限。

超过九项显示“上一页 / 第 X / Y 页 / 下一页”，边界按钮禁用；九项以内不用多余分页条。翻页回到列表起点。切换栏目/筛选时重置到有效页；删除最后一项后夹紧页码，避免空白末页。页数使用 ceil(实际展示块数 / 9)，不能把文件夹中的隐藏单篇计入首页页数。

## 文章详情与 Markdown 内容

页面顺序：返回合集 → 标题 → 作者、原始日期等简短元信息 → 原帖出处 → 内容概述 → 来源内容整理 → 必要的图片补充。AI 问答等现有功能保留，不为采集增加新功能。

- content_notice 使用空字符串，页面不渲染截图中那类固定提示条。
- 默认不生成“整理者建议”和“阅读边界与核对说明”章节；不要改个同义标题再恢复长免责声明或未要求的建议。
- limitations、quality_status: unverified 和来源元数据继续保留，页面删提示不等于事实已验证。具体数字不清或关键材料缺失时，在对应信息旁简短说明，不能为了版面省掉必要语义限定。
- 一个 H1；概述说明具体问题和信息价值；来源内容整理用自然 H3/列表组织，不重复摘要、图片说明和正文，不用“详见原帖”充数。
- 仅保留有信息增量的相关原图，正文引用对应正式资源。原字节/格式不变，图片等比适配（max-width:100%、height:auto），可读图名居中，说明简短。无保留图时省略图片章节，不显示空标题。
- 来源、作者及日期由元数据可靠显示；不把 L 编号或临时全集序号拼进永久标题。正文不重复写一套长元信息清单。

完整 YAML 和批次 schema 见 [atlas.md](atlas.md)，新批次指定 content_format: concise。旧批次不自动批量清理；用户要求修改时按明确范围备份并处理。

## 作者合集元数据

新批次 manifest 使用 author_profile_id（核验后的平台作者 ID）、author_collection_id（如 xhs-<作者ID>）及 author 昵称。每篇元数据使用 source_author_id、同一 author_collection_id、author_collection_title。昵称更改不能创建新合集；不同账号同名不能合并。

已有来源依然跳过重复采集。若要把这些旧篇加入新合集，先核对实际作者身份，在用户授权的合集整理范围内只补必要合集元数据，保留原正文、id、路径和 L 编号，并备份/单独审计这类元数据更新。不要让“跳过已有”产生第二份文件，也不要为了通过旧文件哈希保护悄悄刷新快照；新增校验和已授权更新校验分开处理。

## 验收清单

1. 同一合集在首页仅一块；可读总数与纳入清单一致，无重复单篇。
2. 换两位作者都从 1 开始；第 2 页从 10 开始，跨页无缺漏，整套顺序旧→新；数据库 id、L 编号、路径及引用不变。
3. 搜索后全集序号不重置；筛选清除后顺序和页码有效，超过后端单页上限的数据仍齐全。
4. 用十九条资料验证 9、9、1；九条只有一页；末页下一页禁用，删除末页最后一项不出现空页。
5. 标题、摘要、日期、原帖出处和保留图可读；无固定提示条及两个被移除章节。核对桌面/手机布局及图片比例。
6. 详情返回原合集、原页码；等待列表加载完成再断言。私有笔记/历史可用隔离测试数据，不能冒充用户真实数据验收或修改登录保护。
7. 完整构建、源文件验证、实际索引/RAG 验收和远端发布分别报告。仅更新 skill 不触碰应用；未测项不能写成通过。
