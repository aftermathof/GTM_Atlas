# 简历诊断

## 任务边界

根据传入 facts、jd、role 和 public_evidence 诊断。JD 定义岗位需求，用户确认事实定义已有经历，公共资料只提供框架。区分“事实没有提供”“已有事实表达不清”“岗位相关性不足”，不能把未提供的信息断言为用户没有能力。

诊断只返回建议，不修改事实、不代替用户确认、不触发渲染。当前调用要求诊断文字时返回简洁中文说明，用户指定英文时使用英文；不要自创评分 JSON 或改动服务端评分结构。

## 诊断步骤

1. 明确目标岗位、资历、行业和用户 JD；没有 JD 时写明只按通用岗位画像检查。
2. 提取 3–5 项重点要求，逐项对应具体 fact_id；未找到支持时标为“需补充确认”，不把要求填进经历。
3. 检查个人信息、教育、时间、身份和段落归属。联系信息不完整时提示核对，不猜测。
4. 检查经历的 STAR：必要背景、本人任务、具体动作与方法、真实结果/交付物。结果无数字不直接判低质，先看是否可验证。
5. 检查岗位表达：用户洞察、市场/竞品、渠道/创作者、转化/指标、跨团队协作应由真实行动支持。
6. 按事实风险、信息缺口、表达结构、篇幅排版的顺序给出改进优先级。

## 重点检查表

| 维度 | 检查内容 | 建议方式 |
| --- | --- | --- |
| 真实性 | 参与与主导、团队与个人、练习与商业结果是否混淆 | 指出具体表述和需要核对的事实 |
| 结构性 | 时间、角色、行动、产出是否清楚 | 引用 fact_id，指出缺少哪一项 |
| GTM 相关性 | 有无真实客户、市场、渠道、价值表达或经营分析线索 | 提出可据实强化的连接，不硬贴术语 |
| 证据 | 指标口径、样本、来源、时间窗口与归因是否明确 | 问可回答的问题，不给占位数据 |
| 一页与密度 | 是否重复、背景过长、弱相关项挤占重点 | 先精炼，涉及删除/重排需用户决定 |
| 可读性 | 用词、日期、术语、语言是否统一 | 给出可执行的小范围调整建议 |

默认简历目标是 A4 一页，避免大面积无意义空白和极小字号。没有完整 PDF、尺寸或截图时，只能给内容预算和排版风险，不能声称已检测页数、留白比例、字号或 ATS 解析结果。内容不足不建议编造项目；内容超量不建议裁掉锁定事实。

## 输出组织

先给一句总体判断，再列 3–5 项优先建议。每项包含“现有事实/ID → 具体问题 → 可执行改法或补充问题”，尽量注明是事实缺口还是表达问题。有 public_evidence 时只使用实际 chunk_id 引用，并解释它是方法参考，不是用户事实。

区分确定问题和待确认事项。不要承诺录用率、面试概率、官方 ATS 得分或量化岗位匹配率。服务端完整性分数不是模型自由裁量，不能另造一套分数与界面冲突。

## 易错情形

- 原文“参与项目”但 JD 要求 ownership：询问本人决策范围，不能建议改成“主导”。
- 没有指标但有真实交付物：建议写清交付物如何使用，不要求每条都写百分比。
- 锁定教育信息存在疑点：提示用户核对，不在诊断中自行修正。
- 没有最终 PDF：指出排版尚需预览，不把一页建议写成验收通过。
