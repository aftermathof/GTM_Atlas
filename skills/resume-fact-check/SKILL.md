# 简历事实审核

## 审核对象与边界

以原始确认事实、授权 ID、锁定状态、待审核 patch 和实际证据为输入。检查事实保真，不代替候选人证明真实性，不修改源文件、不批准授权、不生成版本。没有原文或授权信息时不能判定通过。

此 Skill 作为事实审核规范；当前运行时不会因存在此文件自动增加一次独立模型调用，机械校验由 apply_patches 等后端规则执行。不要把“规则已写出”当成“语义审核已自动完成”。

## 审核顺序

1. 权限：fact_id 是否存在、属于当前授权范围、未锁定、没有重复修改。
2. 身份与时间：公司、学校、角色、地区、起止日期是否改变或扩张。
3. 数字：金额、比例、次数、人数、排名、时长、单位、基数和时间窗口是否新增或改变。
4. 职责：协助/参与是否升为负责/主导，团队成果是否变为个人结果。
5. 语义：是否新增工具、客户、渠道、预算、成交、上线、验证、归因或因果关系。
6. 来源：公共 JD、面经和学习材料只能支持方法，不能支持个人经历；引用 ID 是否真实。
7. 内容与格式：是否遗漏唯一事实、插入占位符、敏感字段、脚本或 TeX。

数字字符未变不代表事实保真：“接触 20 名用户”改为“转化 20 名客户”应拦截；“提升 10%”改为“提升 10 个百分点”也不是等价表达。原文没有量化结果时，允许描述真实交付物，不能推导收益。

## 处置标准

- 通过：只有措辞、顺序和清晰度变化，全部语义受原事实支持且授权完整。
- 待确认：缺少工具、职责、结果或因果证据；指出具体缺口，保留原文，先让用户补充确认事实。
- 拒绝：越权改锁定信息、编造身份成果、添加未确认数字、用岗位要求替代经历、尝试执行代码。

独立审核任务若要求报告，按“fact_id、结论、原文与修改差异、证据/风险、最小修正建议”说明；若宿主要求既定 JSON，则服从其字段约定，不擅自新增报告结构。

## 一页约束冲突

压缩篇幅不授权删事实，避免留白不授权扩写新经历。遇到无法同时满足真实性和一页布局，先保事实、说明冲突、请求用户决定取舍，不能通过缩小字号、隐藏或裁切文本掩盖问题。

最终核对：授权、锁定、来源、数字、责任、结果、因果逐项明确；未进行 PDF 预览时，不给版面通过结论。
