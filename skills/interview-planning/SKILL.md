# GTM 模拟面试规划

## 输入与输出

输入为 setup、role_profiles、blueprint 和 authorized_facts。setup 中 count、language、difficulty、role、industry 和 jd 定义当前面试；blueprint 提供题序与参考证据。只返回 JSON：`{"questions":[{"text":"问题正文","dimension":"能力维度"}]}`，不要围栏、答案、评分、简历改写或额外字段。

题数必须等于 setup.count，按数组顺序对应 blueprint。题目至少覆盖三个不同能力维度，不输出空题或重复题，单题不超过宿主 1500 字符限制。遵循设定语言，中文问题不能仅翻译标题就充当英文面试。

## 规划步骤

1. 从 JD 和岗位画像识别关键工作任务，明确实习/校招/有经验等阶段。未提供公司信息时不臆测其招聘标准。
2. 结合 blueprint 的能力维度构造问题，避免与该题证据和评价方向脱节。已有授权简历问题保留其题序，不把其他问题错误标成简历题。
3. 兼顾岗位认知、业务场景、分析与指标、真实行为、协作沟通；以用户岗位为主，不机械覆盖无关销售任务。
4. 依据难度调整信息量和取舍要求，而非堆术语或让新人承担高管职责。
5. 检查题目差异、证据性质、简历授权、可回答性和 JSON 数量。

## 题型与难度

| 难度 | 题目特征 |
| --- | --- |
| 基础 | 给清楚背景，检查概念、职责边界、分析步骤；允许没有实习经历的回答方式 |
| 进阶 | 引入真实约束、指标冲突或资源取舍，要求假设、行动和验证方法 |
| 挑战 | 增加信息不完备、多方目标或复杂归因，检查判断质量，不考凭空知道公司的内部数据 |

行为题使用 STAR 追问框架：背景/目标、本人角色、关键行动、结果与反思；不在问题里暗示用户已有未经确认的成果。情境题明确标注假设，不把假设预算、地区或销量写成实际事实。

## 岗位侧重

- 渠道：客户与分销、库存、返利、动销、合作边界；区分 sell-in 与 sell-out。
- KOL：人群和创作者匹配、内容、合作、归因、成本与品牌风险。
- 增长：漏斗、实验、留存、渠道质量和单位经济性，避免只看下载量。
- PMM：洞察、定位、价值表达、上市和销售赋能。
- GTM 策略：市场选择、细分定位、产品/价格/渠道/推广配合、验证与迭代。

以上是选题方向，不能凌驾于真实 JD；不要把 KOL、PMM、渠道销售混成同一岗位。

## 题目质量与事实边界

每题一个主要考察点，最多附紧密相关的澄清，不在一题里连续提五六个无关问题。避免不同题仅换产品名、反复要求自我介绍或预埋唯一标准答案。

面经作为个人参考，不声称题目一定出现在目标公司面试。仅使用 authorized_facts 中的简历内容，不使用旧版、别人的经历或未经本次授权的私人字段。原文“参与”不能在提问中变成“你主导”。

没有真实案例时可问假设问题，并允许候选人明确说明经验边界。不能问与岗位无关的敏感身份、婚育或歧视性筛选问题。

固定随机种子只控制宿主蓝图抽样，不保证远端模型逐字可复现；不要承诺多次生成完全相同。宿主负责持久化，不在输出中声称已保存。
